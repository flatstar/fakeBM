<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → /api/session | Untrusted raw initData crosses here — must be server-validated |
| Telegram WebView (cross-site iframe) → cookie store | Session cookie must survive a cross-site context |
| proxy.ts vs (mini) layout/handlers | Server Actions bypass proxy → layout/handler is authoritative |
| dev-mock branch → production bundle | Must be dead in production |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-V2 | Spoofing | forged `user.id` / `initDataUnsafe` | mitigate | server `verifyInitData()` = `validate(raw, BOT_TOKEN)`; never trust client identity; forged-signature test is a HIGH gate (must pass before verification) |
| T-01-V2r | Spoofing/Tampering | replayed/stale initData | mitigate | `validate(..., { expiresIn: 30*60 })` on `auth_date` (AUTH-03); expired-fixture test |
| T-01-V14 | Elevation of Privilege | dev-mock bypass shipped to prod | mitigate | hard `NODE_ENV==='development'` guard in `devMockUser` (D-12); unit test proves prod path returns null — HIGH gate |
| T-01-V3 | Tampering/Spoofing | session cookie theft / fixation | mitigate | jose-signed JWT, `HttpOnly` (no JS read), `Secure`, `SameSite=None; Partitioned`, 1h TTL + re-auth on reopen (D-03) |
| T-01-V4 | Elevation of Privilege | Server Action bypassing proxy auth | mitigate | authoritative `requireSession()` in `(mini)/layout.tsx` + per-handler guards, not proxy alone |
| T-01-ID | Information Disclosure | BOT_TOKEN/SESSION_SECRET leak to bundle | mitigate | server-only env; assert no `NEXT_PUBLIC_`; 401 returns generic copy (V7), no validation internals |
| T-01-CHIPS | (auth availability) | cross-site cookie blocked in TG WebView | mitigate | `Partitioned` (CHIPS); real-device verify is a phase gate (plan 04); header-token fallback ready (A3) |
</threat_model>
