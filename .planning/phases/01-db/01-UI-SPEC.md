# Phase 1 — UI Design Contract

> Visual and interaction contract for the 기반 (미니앱 셸 · 디자인 시스템 · 인증/DB 경계) phase.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Source of truth:** This phase has a **pixel-defined prototype** in `design-reference/` (React+Babel,
> handed off from claude.ai/design). This spec does NOT invent a new design — it **extracts and locks**
> the prototype's visual output (exact hex, radii, fonts, shadows, copy, TG shell chrome) so the
> Next.js + Tailwind v4 implementation reproduces it faithfully. Token/value provenance is cited to the
> exact prototype file (e.g. `배달의 만족.html :root`, `ui.jsx`, `app.jsx`, `screens-order.jsx`).
>
> **Scope of THIS phase:** the SHELL + DESIGN SYSTEM only — welcome intro, home shell placeholder,
> TG header, bottom 5-slot nav with center 참기 FAB, theme mechanism, common primitives, font roles,
> copywriting voice. Rich screens (가게/주문/피드/통계/공유) and their screen-level contracts belong to
> their own later phases and are deliberately deferred below.

### Font role contract (LOCKED — Pitfall 7/8)

| Role | Font stack | Applies to |
|------|-----------|-----------|
| `--font-body` | `'Pretendard','BMHanna',-apple-system,sans-serif` | Body, UI labels, **all ₩/numbers/kcal/stats** (tabular-nums) |
| `--font-display` | `'BMHanna','Pretendard',sans-serif` | Screen titles, section headings, wordmark "배달의 만족", FAB label |
| `--font-chunky` | `'BMDohyeon','Pretendard',sans-serif` | Big hero stat numbers only (willpower hero amount, stat tiles) |

**HARD RULE — money/number routing (D from CONTEXT 금액·숫자 Pretendard 라우팅, Pitfall 7):**
Every `₩`, count, kcal, and statistic MUST render in **Pretendard** with `font-variant-numeric: tabular-nums`,
NEVER in a BM font. BM Hanna's ₩ glyph renders as a narrow `~` (proven in `design-chat.md`). Formatters
`fmtWon` (`'₩' + n.toLocaleString('ko-KR')`) and `fmtNum` are ported to `lib/` and always output into a
Pretendard-classed span.

**HARD RULE — Korean line breaking (Pitfall 7):** short Korean labels (category names, search text,
location "우리집") use `white-space: nowrap` and/or `word-break: keep-all` to prevent the wide BM font from
splitting "치킨" → "치/킨".

**HARD RULE — emoji whitelist (D specifics, Pitfall 8):** only render emoji verified across Telegram
WebView (iOS/Android). The "참기" / willpower hand is **✋ (U+270B)**, NEVER 🫷 (U+1FAF7) — 🫷 rendered as
tofu in the prototype and was replaced. Do not depend on emoji alone to carry meaning.

## Spacing Scale

Implementation uses a 4px base scale. The prototype mixes a few off-grid display values (status-bar
54px, header 50px/52px, FAB 58px, etc.) — these are **fixed chrome dimensions**, listed under Exceptions,
not free-form spacing.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, stepper button gaps, badge inset |
| sm | 8px | Compact element spacing, nav padding |
| md | 16px | Default screen horizontal padding (`16px`), card-to-card gap baseline |
| lg | 24px | Section breaks below category grid / restaurant list |
| xl | 32px | Major layout gaps |
| 2xl | 48px | Empty-state vertical breathing |
| 3xl | 64px | Page-level spacing |

**Radii (LOCKED — from prototype):**

| Radius | Value | Usage |
|--------|-------|-------|
| Card | **18px** | `Card` primitive (`ui.jsx`) |
| Pill | **999px** | StatBadge, tag pills, search-count badge, toast, category "전체보기" chip |
| Tile (sm) | **14px** | Search pill, food/menu tiles, hero icon box, dark notice box |
| Tile (md) | **16px** | Category icon tiles, FoodTile default, `TgMainButton` button |
| Stepper | **9–11px** | Qty +/- buttons (Phase 2 detail) |

**Shadow recipe (LOCKED):**

| Token | Value | Usage |
|-------|-------|-------|
| `--shadow` | `0 8px 22px -10px rgba(150,70,30,.18)` | Default card shadow (warm cast) |
| FAB shadow | `0 8px 18px -4px rgba(255,90,51,.6)` | Center 참기 FAB |
| MainButton shadow | `0 8px 20px -6px rgba(255,90,51,.5)` | `TgMainButton` (coral) |
| Search pill shadow | `0 6px 16px rgba(180,60,30,.18)` | Home search pill on coral header |
| Willpower hero shadow | `0 12px 28px -10px rgba(40,20,8,.5)` | Dark hero card |

Exceptions (fixed chrome, not spacing tokens):
- Status-bar safe-area block: **54px** (`app.jsx`) — replace with `env(safe-area-inset-top)` + TG theme in impl.
- TG header height: **50px** (`TgHeader`, `ui.jsx`).
- In-screen SubBar height: **52px** (`SubBar`).
- Bottom nav: padding `8px 8px 22px`; center FAB **58×58** with `4px` surface border, offset `top: -26px`.
- `TgMainButton`: `min-height 54px`, bottom padding `calc(14px + env(safe-area-inset-bottom))`.
- Icon touch buttons: 28–34px (steppers); nav icons 24px. Use `dvh`/`svh` for full-height (Pitfall 10).

## Typography

Sizes are taken verbatim from the prototype. Phase 1's visible surface uses the subset below; the
"Display" row is the heading scale and "Hero" is the chunky stat scale.

| Role | Size | Weight | Line Height | Font |
|------|------|--------|-------------|------|
| Body | 13px | 500–600 | ~1.4 | Pretendard (`--font-body`) |
| Body-emphasis / UI label | 14–15px | 600–700 | ~1.4 | Pretendard |
| TG header title | 16px | 700 | 1.1 | Pretendard |
| TG header subtitle ("mini app · bot") | 11px | 400 | 1.1 | Pretendard, color `--tg-sub` |
| Section heading | 17px | 800 | 1.2 | BMHanna (`--font-display`) |
| Screen title (SubBar / wordmark) | 18px | 800 | 1.2 | BMHanna |
| Display large (rest name detail) | 20–22px | 800 | 1.2 | BMHanna |
| Hero stat number (chunky) | 24px | 800 | 1.2 | **BMDohyeon** (`--font-chunky`), tabular-nums |
| FAB label "참기" | 10px | 800 | 1.0 | Pretendard |
| Nav label | 10.5px | 500 (inactive) / 700 (active) | 1.0 | Pretendard |

Notes:
- The prototype declares many weights; for the contract treat **two primary weights** — **regular/medium
  (500)** for body/secondary and **bold (700–800)** for emphasis/headings. BM display fonts read as a
  single heavy weight.
- All numeric content: `font-variant-numeric: tabular-nums` + Pretendard (see Font role contract).

### Theme mechanism — coral ↔ mint (D-04/05/06 — MECHANISM ONLY this phase)

- Default theme is **coral** (`--primary` = `#FF5A33`). A second **mint** theme (배민 오마주) is wired as a
  CSS-variable swap on a root `data-theme` attribute (or class). Phase 1 ships the **mechanism + both
  palettes only**; the user-facing toggle lands in **Phase 5 (MY/설정)** — do NOT render a toggle UI here.
- Swap derivation matches the prototype (`app.jsx` rootVars): given a primary `P`,
  `--primary-soft = color-mix(in srgb, P 13%, white)`, `--primary-ink = color-mix(in srgb, P 86%, black)`.
- **Mint palette (LOCKED):** `--primary: #13C5B8`, `--primary-soft: color-mix(in srgb, #13C5B8 13%, white)`,
  `--primary-ink: color-mix(in srgb, #13C5B8 86%, black)`. (Mint is the only retained Tweaks option; the
  5-color picker, title-font picker, and wait-time slider are REMOVED per D-04.)
- Persisted theme preference lives on the `users.theme` column (`coral` | `mint`) — D-06. No localStorage
  for theme (the welcome-intro "first visit" flag may use localStorage — D-09).
- IP guard (Pitfall 12): mint is an *homage* swap of the accent only — do NOT clone 배민's logo/mascot/
  wordmark. The wordmark stays "배달의 만족".

Coral identity, parody wordmark "배달의 만족", tagline "시켜놓고, 참는다".

| Element | Copy |
|---------|------|
| Wordmark | 배달의 만족 |

| TG header subtitle | mini app · bot |
| Welcome intro headline (discretion, in-tone) | 시켜놓고, 참는다 |
| Welcome intro primary CTA | 시작하기 (or in-tone equivalent; `TgMainButton`) |
