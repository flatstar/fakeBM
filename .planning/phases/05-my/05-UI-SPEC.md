# Phase 5 — UI Design Contract (통계 & MY)

> Visual and interaction contract for the 통계 & MY phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Source of truth:** This phase has a **pixel-defined prototype** for the stats screen
> (`design-reference/screens-social.jsx` §`StatsScreen` L101–168) and a **fully-locked design system**
> already ported in Phase 1 (`01-UI-SPEC.md` → `app/globals.css` `@theme`). This spec does NOT invent a new
> design — it **extracts and locks** the prototype's `/stats` output, then specifies only the two surfaces the
> prototype does not cover: the **`/my` screen** (no prototype mockup) and **empty states** (0-인증).
>
> **Inherits wholesale from `01-UI-SPEC.md` (do not re-derive):** spacing scale, radii, shadows, full color
> token set, font role contract, ₩/number HARD RULE, emoji whitelist, Korean line-break rule, `Card`/`Body`/
> `BottomNav`/`StatBadge`/`Avatar`/`Icon` primitives. This file restates only the values this phase renders and
> the deltas it introduces.

| Token | Value | Usage this phase |

**Radii (inherited, LOCKED):** Card **18px** (`Card` primitive); conversion cards, hero, tiles, chart card all use the `Card` primitive radius. Pill **999px** (summary chips if any). Weekly bar radius **7px** (prototype L141 — fixed chrome, not a spacing token).

**Shadows (inherited):** default `--shadow-card` on every `Card`. **Hero card exception (LOCKED from prototype L112):** coral gradient hero uses a stronger custom shadow `0 16px 32px -12px rgba(232,67,31,.6)` — port verbatim, do not substitute `--shadow-card`.

**Exceptions (fixed chrome, not spacing tokens):**
- Weekly chart plot height: **110px** (`height: 110`), max bar height **84px**, min bar height **4px** (D-06 future/empty days).
- Hero card inner padding: **20px**.
- Conversion card padding: **13px 15px**; 3-tile padding **14px 8px**.
- 🔥 hero watermark: `fontSize 96, opacity .16`, absolute `right:-10 top:-10` (prototype L113).
- BottomNav + 참기 FAB: inherited from Phase 1 (`/stats`·`/my` slots already wired, L31–32 — adding pages activates tabs).

## Typography

Sizes are taken **verbatim from the prototype StatsScreen** and snapped onto the Phase-1 closed token set. No new sizes are introduced beyond the Phase-1 scale (`--text-micro` … `--text-hero`).

| Role | Size | Weight | Line Height | Font | Used for |
|------|------|--------|-------------|------|----------|
| Hero amount (chunky) | 40px | 800 | 1.2 | **BMDohyeon** (`--font-chunky`), tabular-nums | "이번 달 아낀 돈" figure (prototype L115) — the one oversized hero number |
| Screen title (chunky) | 24px | 800 | 1.2 | BMDohyeon | "내 절제력 통계" / "MY" title (L108) |
| Tile value (chunky) | 19px | 800 | 1.0 | BMDohyeon, tabular-nums | 3-tile big numbers (kcal·번 참음·연속일) |
| Section heading | 14–16px | 800 | 1.2 | BMHanna (`--font-display`) | "이번 주 아낀 돈" (14), "그래서 이만큼이에요" (16) |
| Body / UI label | 13–13.5px | 600–700 | ~1.4 | Pretendard (`--font-body`) | hero sublabels, conversion card text, profile name/handle |
| Tile label / caption | 10.5–12.5px | 500–600 | 1.3 | Pretendard | tile unit labels, hero streak line, conversion suffix |
| Bar value / micro | 9.5px | 700 | 1.0 | Pretendard, tabular-nums | weekly bar "{k}" amount + 요일 labels (11px) |

Notes:
- **Two primary weights** (Phase-1 contract): regular/medium **500–600** for body/secondary, bold **700–800** for emphasis/headings/numbers. BM fonts read as a single heavy weight.
- **HARD RULE (inherited):** every ₩/kcal/count/stat renders in **Pretendard `tabular-nums`** via `<Won>`/`<Num>` (`lib/format.ts`). The BMDohyeon hero/tile numbers above are **digit-only stat figures** rendered through the chunky font per the prototype — but any value carrying a `₩` glyph routes through Pretendard `<Won>` (BMHanna ₩ renders as a narrow `~`; see Phase-1 D / 01-03 decision "Won wrapper over chunky digits"). The hero "아낀 돈" amount therefore renders via the Pretendard `<Won>` wrapper sized to the hero scale, NOT raw BMDohyeon — matching the established 01-03 routing.
- **CLOSED SCALE:** adding a new size requires updating this contract first.

## Color

Inherited token set from `01-UI-SPEC.md` / `app/globals.css` `@theme` (coral default; mint swap via `data-theme="mint"`). 60/30/10 split:

| Role | Value | Usage this phase |
|------|-------|------------------|
| Dominant (60%) | `#FFF7F1` (`--color-bg`) | App/screen background (`Body`) |
| Secondary (30%) | `#FFFFFF` (`--color-surface`) | All cards: 3 tiles, weekly-chart card, conversion cards, /my profile + summary cards, BottomNav |
| Accent (10%) | `#FF5A33` (`--color-primary`) | See reserved list below |
| Second semantic | `#15A24A` (`--color-green`) savings · `#B5760A` (`--color-amber-ink`) streak — tinted stat colors, NOT destructive |

**Accent reserved for (coral `--color-primary` — explicit list, never "all interactive elements"):**
- **Hero card coral gradient** — `linear-gradient(135deg,#FF6A3D,#E8431F)` (prototype L112; the hero's coral identity, white text on top). This is the dominant accent surface of `/stats`.
- **Weekly chart max-day bar** — the single tallest bar = `--color-primary`; **all other bars = `--color-primary-soft`** (`#FFE9E1`) (prototype L141, CONTEXT specifics). This is the deliberate "one hero, rest soft" emphasis pattern.
- **kcal tile value** — `--color-primary` (prototype L122 `c: 'var(--primary)'`).
- **Active bottom-nav tab** (chart/user icon + label turn coral) — inherited Phase-1 behavior.
- **Empty-state CTA** (`TgMainButton` coral fill or coral link "첫 인증하러 가기") — see Copywriting.
- **/my summary "자세히 →" link to /stats** — coral text + `chevron` icon.

**Semantic stat colors (NOT accent, from prototype tiles L122–124):**
- "번 참음" tile value → `--color-green` (`#15A24A`).
- "일 연속" / streak tile value → `--color-amber-ink` (`#B5760A`).
- Hero streak/누적 sublines → white at `opacity .9–.92` on the coral gradient.

**Destructive:** **None in this phase.** `/stats` and `/my` are read-only aggregation surfaces — no delete/irreversible action. The /my own-records list reuses `FeedCard` in **read-only mode** (LikeButton + ReportMenu suppressed, see Component Inventory) so even the inherited report (hide) action is absent here. No destructive-confirmation contract is owed.

## /my Screen Layout (NEW — discretion surface, locked here)

`/my` is a private self-view RSC page (`requireSession` gate). Vertical stack, screen padding `16px 16px 0`, `Card`-to-`Card` gap 14px, on `--color-bg`:

1. **Screen title** — "MY" or "내 정보" (24/800 chunky, optional). Keep minimal — the profile card carries identity.
2. **Profile header card** (D-09) — Avatar + real name + "피드에선 {handle}로 보여요" note.
3. **Cumulative summary card** (D-10) — 누적 절약/kcal/스트릭 teaser + coral "자세히 → /stats" link.
4. **"내 인증 기록" heading** (14–16/800 display) + own-records `FeedCard[]` (read-only). If 0 records → empty state (below).
5. **MY footer** (inherited Phase-1 copy) — "배달의 만족 · 시켜놓고, 참는다" (small, ink3, centered).

The Phase-1 contract also parks the **coral↔mint theme toggle UI** in "Phase 5 (MY/설정)". This phase's CONTEXT/RESEARCH do **not** scope the toggle into STATS-01..05, so it is **NOT required by this UI-SPEC**; if the planner elects to surface it, it must use the locked mechanism (`users.theme` column, `data-theme` swap) and the IP guard (mint = accent-only homage, wordmark stays "배달의 만족"). Treated as out-of-contract-scope optional, not a deliverable here.
