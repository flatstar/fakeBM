<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| session → /admin page | Only ADMIN_TG_IDS sessions may see the route; others get notFound |
| client → /api/admin/* | Every admin mutation re-verified server-side; the page guard does not extend to the API |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-17 | Elevation of Privilege | direct call to /api/admin/delete by a non-admin | mitigate | Every /api/admin/* handler re-checks isAdmin(tgId) after requireSession → 404 for non-admins (Pitfall 4); never relies on the page guard alone |
| T-04-18 | Information Disclosure | /admin route existence revealed to non-admins | mitigate | Non-admins get notFound() (not 403) at both the page guard and the API — the route/endpoint never confirms itself (D-14/15) |
| T-04-19 | Information Disclosure | ADMIN_TG_IDS leakage | mitigate | isAdmin reads ADMIN_TG_IDS server-only at call time; never NEXT_PUBLIC_; the allowlist is never sent to the client (D-14) |
| T-04-20 | Tampering | admin body mass-assignment | mitigate | zod accepts only postId; no deletedAt/hiddenAt value taken from the body — server sets the timestamp/null |
| T-04-21 | Information Disclosure | admin shows raw author identity | mitigate | Admin list renders handleFor(tgId) — the anonymous handle, never Telegram username/firstName (D-01) |
| T-04-SC | Tampering | npm installs | accept | No package installs this phase |
</threat_model>
