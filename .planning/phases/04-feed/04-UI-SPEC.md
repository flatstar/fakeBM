# Phase 4 — UI Design Contract

> Visual and interaction contract for the **명예의 전당 피드 (+ 좋아요 + 모더레이션)** phase.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Source of truth:** This phase has a **pixel-defined prototype** in `design-reference/screens-social.jsx`
> (`FeedScreen` / `PostCard` / `PostPhoto`) and a **fully-locked design system** already ported in Phase 1
> (`01-UI-SPEC.md` — Tailwind v4 `@theme` tokens, BM/Pretendard fonts, coral identity, emoji whitelist,
> ₩ HARD RULE). This spec does NOT invent a new design — it **extracts and locks** the prototype's feed
> card, then specifies the three discretion surfaces the prototype does not fully cover (report affordance,
> empty/loading states, the `/admin` moderation screen).
>
> **Scope of THIS phase:** `/feed` 명예의 전당 screen + `PostCard` (like + report ONLY — 응원/북마크 dropped
> per CONTEXT discretion) + report reason picker + `/admin` operator moderation list. All other screens
> (가게/주문/대기/인증/통계/공유) are owned by their own phases.
>
> **Token mapping note:** the prototype uses raw CSS vars (`var(--primary)`, `var(--bg)`, `var(--shadow)`).
> These map 1:1 to the ported Tailwind v4 keys (`var(--color-primary)`, `var(--color-bg)`,
> `var(--shadow-card)`) per the 01-03 decision. **Always use the ported `--color-*` / `--shadow-card` keys.**

### Carried-forward HARD RULES (from 01-UI-SPEC — still binding)

- **Money/number routing (Pitfall 7):** every `₩` / like count / kcal / streak-day number renders in
  **Pretendard tabular-nums** via `Won`/`Num` — NEVER a BM display font. The feed payoff badges
  (`아낌 ₩…` / `−…kcal`) and the like count MUST use these wrappers (Pitfall 5 of 04-RESEARCH).
- **Korean line breaking:** short Korean labels (`인증`, `…일째`, diet pill, reason chips) use
  `white-space: nowrap` / `word-break: keep-all` to stop BM font splitting (e.g. "스팸" → "스/팸").
- **Emoji whitelist:** only use emoji verified across Telegram WebView. This phase uses
  `🏆 🥗 🤤 🔥` (all present in the prototype and shipped in Phase 1–3). The willpower hand is
  **✋ (U+270B)**, NEVER 🫷 (U+1FAF7). Do not depend on emoji alone to carry meaning.

## Color

Palette is the locked Phase-1 token set; 60/30/10 split below. Coral accent stays reserved (no
"all interactive elements" coral wash). Phase 4 introduces the **first destructive flows** in the app
(report→hide, operator delete) — destructive color contract defined below.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFF7F1` (`--color-bg`, cream) | Feed background, receipt-chip fill (`background: var(--color-bg)`), `/admin` background |
| Secondary (30%) | `#FFFFFF` (`--color-surface`) | Post cards, reason sheet, `/admin` rows, bottom nav |
| Accent (10%) | `#FF5A33` (`--color-primary`, coral) | See reserved list |
| Destructive / second semantic | **`#D8431F` (`--color-primary-ink`, coral-ink)** for destructive **text/affordance** (report confirm, operator 삭제 button). There is no separate red token — coral-ink is the locked destructive tone (01-UI-SPEC). Operator **복구(restore)** uses `--color-green`. |

**Accent (coral `--color-primary`) reserved for — explicit list:**
- The **liked heart** fill + count (`fill: var(--color-primary)` when liked; `--color-ink2` when not).
- The "+ 나도 참고 인증하기" **CTA** (dashed coral border + `--color-primary-soft` fill + coral text).
- The **empty-state** primary action (same CTA).
- The infinite-scroll **loading spinner** tint.
- Active bottom-nav `/feed` tab (already wired in `BottomNav.tsx`).

NOT coral: card chrome, receipt chip, author handle, meta, report trigger (neutral `--color-ink3` until pressed).

**Semantic tints (reuse `StatBadge` `TINT`):**
- 아낌(savings): `Won` value, `--color-green` text on `--color-green-soft` (`TINT.save`).
- −kcal: `Num` value, `--color-primary-ink` text on `--color-primary-soft` (`TINT.kcal`).
- 🔥 streak day: `--color-amber-ink` text on `--color-amber-soft` (`TINT.streak`).
- 식단(diet) pill: `--color-green` text on `--color-green-soft`.

**Destructive-flow color rules:**
- Report-menu **trigger** is neutral (`--color-ink3`); the **신고하기** entry inside the menu/sheet is
  `--color-primary-ink` (coral-ink), signalling consequence without a foreign red.
- `/admin` **삭제(soft delete)** button: `--color-primary-ink` text/border; **복구(restore)** button:
  `--color-green` text/border. Both on `--color-surface`.

## Interaction Contracts

| Interaction | Contract |
|-------------|----------|
| **Like toggle** | Optimistic flip of heart fill + count on tap → `POST /api/posts/[id]/like` → **reconcile UI to returned `{liked,count}`** (set, never increment). Idempotent: double-tap/retry converges. Disabled/no-op on hidden/deleted posts (they won't appear). |
| **Report** | `⋯` trigger → bottom sheet → tap a reason chip → `POST /api/posts/[id]/report` → on success the card is **immediately removed** from the viewer's list (D-10 instant hide) + a toast "신고했어요. 검토 후 처리돼요." Self-owned cards show no report trigger (D-13). Duplicate report by same user is a silent no-op (still removes the card). |
| **Infinite scroll** | First page server-rendered (RSC). "더 보기" (or sentinel) requests the next keyset page; new cards append below with no duplicate/gap (composite `(createdAt,id)` cursor). Tail states: spinner while loading → "여기까지예요 🙌" when exhausted. |
| **Empty feed** | 0 posts → `FeedEmptyState` with the CTA routing to the order flow (참기 start). |
| **CTA "+ 나도 참고 인증하기"** | Navigates to the order/참기 entry (same destination as the center FAB) so the user can create a post. |
| **/admin 삭제** | Operator taps 삭제 → confirm ("이 인증을 영구 삭제할까요? 되돌릴 수 없어요.") → `POST /api/admin/delete` (sets `deletedAt`). Destructive: requires the confirm step. |
| **/admin 복구** | Operator taps 복구 → `POST /api/admin/restore` (clears `hiddenAt`) → post returns to public feed. Non-destructive, no confirm needed. |
